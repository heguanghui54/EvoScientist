### 1. Title
**U-Calibrate: Reducing False Positives in AI Detection via Cross-Domain Uncertainty Calibration and Stylistic Sensitivity**

### 2. Problem and Motivation
Current AI-generated content (AIGC) detectors—whether based on supervised classifiers (e.g., RoBERTa-based) or zero-shot statistical measures (e.g., DetectGPT)—suffer from high False Positive Rates (FPR), particularly when evaluating non-native English speakers, technical documentation, or highly structured academic writing. This "bias toward formality" leads to the unfair penalization of human authors whose natural writing style exhibits low perplexity or follows rigid templates. To be viable for high-stakes environments like academia or journalism, detectors must distinguish between "machine-like" human writing and actual LLM-generated output.

### 3. Core Hypothesis
Integrating a **Stylistic Uncertainty Layer (SUL)**—which combines Monte Carlo (MC) Dropout for model uncertainty with a domain-specific "human-formal" reference cluster—will significantly reduce false positives by identifying and reclassifying low-perplexity human text that standard detectors typically mislabel as AI.

### 4. Method
The proposed workflow follows a three-stage verification pipeline:

1.  **Phase 1: Multi-Model Inference.** Input text is passed through a standard transformer-based classifier (e.g., RoBERTa-large-detector). We apply **MC Dropout** during inference (running 10+ passes) to generate a distribution of probability scores rather than a single point estimate.
2.  **Phase 2: Uncertainty Gating.** If the variance of the probability scores exceeds a predefined threshold (indicating model "confusion"), the system triggers a **Semantic Divergence Check**.
3.  **Phase 3: Reference Clustering.** We map the latent representations of the input text against a pre-computed embedding space of "Human-Formal" text (e.g., technical manuals, TOEFL essays). If the input text falls within the high-density human cluster, the initial "AI" label is overridden or flagged as "Inconclusive/Human-like."
4.  **Implementation Milestone:**
    *   *Month 1:* Benchmark existing detectors on non-native English datasets.
    *   *Month 2:* Develop the MC Dropout uncertainty wrapper.
    *   *Month 3:* Build the reference cluster using Contrastive Learning (SimCLR-style) to maximize the distance between human-formal and AI-formal embeddings.

### 5. Dataset or Benchmark
The study will use a composite dataset to stress-test the FPR:
*   **Human-Formal Subset:** The *C-SAPA* (Chinese-Speaking Learners of English) corpus and the *ArXiv* technical abstracts (pre-2022) to represent high-complexity human writing.
*   **AI Subset:** Content generated by GPT-4, Claude 3.5 Sonnet, and Llama-3-70B using "academic" and "technical" prompts.
*   **Control Subset:** The *Writing Prompts* dataset (standard human creative writing).

### 6. Evaluation Metrics
*   **Primary Metric:** False Positive Rate (FPR) at a fixed True Positive Rate (TPR) of 90% (FPR@90TPR).
*   **Secondary Metrics:**
    *   Area Under the Receiver Operating Characteristic (AUROC).
    *   Brier Score (to measure the calibration of predicted probabilities).
    *   FPR specifically on the non-native English speaker (NNES) subset.

### 7. Baselines
*   **Binary Classifier:** A standard RoBERTa-large model fine-tuned on the OpenGPT dataset.
*   **Statistical Detector:** *DetectGPT* (using curvature of log-likelihood).
*   **Commercial/API Baseline:** GPTZero or similar publicly accessible detection API (as a black-box comparison).

### 8. Ablations
*   **W/O MC Dropout:** Testing the system using only the Reference Clustering to see if latent mapping alone is sufficient.
*   **W/O Reference Clustering:** Testing if uncertainty estimation alone (MC Dropout) captures the stylistic nuances of human-formal text.
*   **Fixed vs. Dynamic Thresholding:** Comparing a global decision threshold against a domain-specific threshold (e.g., different thresholds for creative vs. technical text).

### 9. Failure Modes and Feasibility Risks
*   **Sensitivity Loss:** The primary risk is that by reducing false positives, the model may become overly conservative and fail to detect sophisticated AI content that mimics human "burstiness" (False Negatives).
*   **Computational Overhead:** Running 10-20 inference passes for MC Dropout increases latency, making it less suitable for real-time applications without optimization.
*   **Data Drift:** As LLMs evolve to be more "human-like" in their formal structures, the distance between the "Human-Formal" cluster and "AI" embeddings may shrink, requiring constant retraining of the reference space.
