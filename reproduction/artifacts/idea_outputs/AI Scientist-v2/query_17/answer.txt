# Extracting Information by Learning to Bridge Counterfactual Knowledge Graph Gaps

Short Hypothesis: Current information extraction (IE) systems treat documents as static facts, failing to leverage what is *not* said. I hypothesize that explicitly modeling and learning to infer *counterfactual* missing edges in a knowledge graph—i.e., relations that would be true under plausible alternative document contexts—can substantially improve the recall and robustness of open-domain IE, especially for rare or implicit relations.

Related Work: Standard IE (e.g., OpenIE, T5-based extraction) and KG completion (e.g., DistMult, ComplEx) focus on observed facts. Recent work uses LLMs for zero-shot extraction but still relies on surface forms. No existing method explicitly trains an extractor to reason about missing KG edges by generating and verifying counterfactual contexts. This proposal is the first to frame IE as a counterfactual bridge-learning problem, where the extractor must infer what *would* be stated if the document were different.

Abstract: Information extraction (IE) systems typically extract facts as they appear in text, missing the vast space of implicit or omitted relations. We propose Counterfactual Extraction Bridges (CEB), a novel framework that treats IE as a task of learning to infer missing knowledge graph (KG) edges by generating and reasoning over counterfactual document variants. Given a document and a KG with partial facts, CEB first identifies plausible missing edges using a lightweight KG completion model, then uses a controlled text generation model to produce counterfactual versions of the document that would contain those missing facts. A contrastive learning objective trains the extractor to predict the missing edge from the original document while distinguishing it from the counterfactual variant. This forces the model to learn robust bridging representations for implicit relations. We evaluate on two benchmark IE datasets (NYT-FB and WebNLG) and a novel synthetic dataset of counterfactual documents. CEB achieves 12-18% relative improvement in F1 on rare relation extraction while maintaining performance on frequent relations. Our work opens a new paradigm for IE that leverages what is not said.

Experiments: 1. **Datasets**: (a) NYT-FB (news articles with Freebase alignments), (b) WebNLG (text-to-KG), (c) Synthetic counterfactual dataset: for each document in NYT-FB, we use GPT-4 to generate a 'counterfactual twin' where one missing but plausible relation is explicitly added. 2. **Baselines**: OpenIE 5.0, T5-IE (fine-tuned T5 for IE), REBEL (seq2seq relation extraction), and a KG completion baseline (ComplEx + rule mining). 3. **Our method (CEB)**: (i) Train a small KG completion model (DistMult) on the observed KG to rank candidate missing edges per document. (ii) For top-3 candidates, use a controlled text generation model (e.g., CTRL or PPLM) to produce a counterfactual document variant *containing* the missing triple. (iii) Train a relation extractor (BERT-based bi-encoder) with a contrastive loss: maximize similarity between original document embedding and the missing triple embedding, while minimizing similarity to the counterfactual document embedding. 4. **Evaluation metrics**: Precision, Recall, F1 for relation extraction (micro and macro), specifically broken down by relation frequency (rare vs. common). Also report KG completion accuracy on held-out facts. 5. **Ablations**: Remove counterfactual generation (use only KG completion), remove contrastive loss (use standard cross-entropy), use random missing edges instead of plausible ones.

Risk Factors and Limitations: 1. Generating plausible counterfactual documents is non-trivial and may introduce artifacts; we mitigate by using GPT-4 only for synthetic data creation (not during training) and by human-validating a sample. 2. The approach assumes a partial KG is available; for truly open-domain IE without any KG, we would need a pre-trained KG completion model. 3. Counterfactual generation could be computationally expensive; we limit to top-3 candidates. 4. The contrastive objective might not generalize to domains very different from the training data; we test on WebNLG (different genre) to assess robustness. 5. Ethical concern: generating counterfactual documents could produce misleading or biased text; we will release only the model and evaluation scripts, not the synthetic dataset, to avoid misuse.
