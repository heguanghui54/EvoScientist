# Capability Gradient Descent: Learning Orthogonal Skill Subspaces for Dynamic LLM Control

Short Hypothesis: We hypothesize that the diverse capabilities of a large language model (e.g., reasoning, coding, creativity, factual recall) are encoded in linearly separable and approximately orthogonal directions in the model's residual stream activation space. By learning a set of 'capability basis vectors' via a novel training objective that encourages orthogonality and functional specificity, we can dynamically compose these vectors to precisely control which capabilities are expressed during inference, enabling fine-grained behavior modulation without any fine-tuning or architectural changes.

Related Work: Current approaches to controlling LLM behavior include prompt engineering (unreliable), fine-tuning (expensive, risks catastrophic forgetting), and activation steering (e.g., using contrastive pairs to find steering vectors for concepts like honesty or sentiment). However, existing steering vector methods typically target single, high-level concepts and do not systematically disentangle the full spectrum of technical capabilities. Model editing methods (e.g., MEMIT, ROME) modify factual knowledge but not general skills. This proposal introduces a principled framework to learn a complete, orthogonal basis of capability directions directly from data, and a learned gating mechanism to compose them. This is distinct from prior work because it (1) explicitly enforces orthogonality to minimize interference, (2) targets multiple fine-grained capabilities simultaneously, and (3) uses a lightweight controller to dynamically mix capabilities per input.

Abstract: Large language models (LLMs) exhibit a wide range of capabilities, from reasoning and coding to creative writing and factual recall. However, controlling which capabilities are expressed during inference remains a challenge. Prompt engineering is brittle, fine-tuning is costly and risks catastrophic forgetting, and existing activation steering methods typically target single, coarse concepts. In this work, we propose Capability Gradient Descent (CGD), a method to learn a set of orthogonal 'capability basis vectors' in the residual stream of a frozen LLM. Our approach involves two stages: (1) Capability Basis Learning: We collect datasets that isolate specific capabilities (e.g., a reasoning dataset, a coding dataset, a creative writing dataset). For each capability, we learn a steering vector by maximizing the likelihood of that capability's outputs while minimizing interference with others, using a novel loss function that combines a capability-specific objective with an orthogonality penalty across all vectors. (2) Dynamic Capability Composition: We train a small, lightweight 'capability controller' (e.g., a 2-layer MLP) that, given an input embedding, predicts a set of mixing coefficients for the capability vectors. At inference, the final activation is the base activation plus a weighted sum of the capability vectors, effectively modulating the model's behavior. We evaluate on a suite of benchmarks spanning reasoning (GSM8K, MATH), coding (HumanEval, MBPP), creative writing (perplexity on poetry, story coherence), and factual accuracy (TriviaQA, MMLU). We hypothesize that CGD will enable fine-grained, dynamic control over capabilities, outperform prompt engineering and single-vector steering, and generalize to unseen capability combinations. This work provides a new paradigm for model control that is efficient, interpretable, and scalable.

Experiments: We will conduct experiments on a 7B-parameter open-source LLM (e.g., Llama 2 or Mistral).

**Stage 1: Capability Basis Learning**
1. Collect four datasets, each designed to isolate a specific capability:
   - Reasoning: GSM8K (math word problems) + a subset of PRM800K (process supervision).
   - Coding: A filtered subset of CodeAlpaca (instruction-following code tasks).
   - Creativity: A dataset of story prompts + high-perplexity continuations from GPT-4 (to encourage novelty).
   - Factuality: TriviaQA + a subset of Natural Questions (factual QA).
2. For each capability c, we learn a steering vector v_c (in the residual stream at a middle layer, e.g., layer 16 of 32) by gradient descent. The objective: maximize the log-likelihood of the target capability's outputs on its dataset, while adding a regularization term that penalizes the cosine similarity between v_c and all previously learned vectors (enforcing orthogonality). We use a held-out validation set to prevent overfitting.
3. Evaluate the isolated effect of each vector: For each capability, we measure performance on its benchmark when the vector is applied alone (with strength alpha=1) vs. without steering. We also measure interference: apply v_reasoning to a coding task and measure performance drop. We expect low interference due to orthogonality.

**Stage 2: Dynamic Capability Composition**
1. Create a 'compositional' dataset: For each input, we randomly sample a combination of capabilities to express (e.g., 'reasoning + coding' for a math coding problem, or 'creativity + factuality' for a historical fiction prompt). We use GPT-4 to generate target outputs for these combinations.
2. Train a small controller (2-layer MLP, hidden dim 256) that takes the input embedding (from the model's embedding layer) and outputs a 4-dimensional vector of mixing coefficients (one per capability, softmax-normalized). The controller is trained to minimize the negative log-likelihood of the target outputs under the composed steering: activation = base_activation + sum_i coeff_i * v_i. The controller weights are updated, while the base model and v_i remain frozen.
3. Evaluate on held-out compositional tasks: e.g., 'write a poem about quantum mechanics that is factually accurate' (creativity + factuality), 'solve this math problem and explain the reasoning step-by-step in code' (reasoning + coding). Compare against: (a) base model, (b) prompt engineering (e.g., 'think step by step'), (c) single best steering vector for each task, (d) an oracle that uses the true capability combination.

**Evaluation Metrics:**
- Task-specific accuracy (e.g., pass@1 for coding, exact match for reasoning, BLEU for creative writing, F1 for factuality).
- Interference score: average performance drop on other tasks when a single vector is applied.
- Controllability score: correlation between the controller's predicted coefficients and the ground-truth capability requirements (measured via human annotation or GPT-4 judgment).
- Ablation: test with random coefficients to verify the controller is learning meaningful combinations.

Risk Factors and Limitations: 1. **Linearity assumption**: The hypothesis that capabilities are encoded in linear, orthogonal directions may be too strong. If capabilities are highly non-linear or entangled, the orthogonal basis may not capture them well. We may need to explore non-linear transformations or multiple vectors per capability.
2. **Data quality**: The 'capability isolation' datasets are imperfect; they may contain spurious correlations. For example, the 'creativity' dataset might inadvertently include factual errors. Careful data curation and filtering are essential.
3. **Controller generalization**: The controller is trained on a limited set of capability combinations. It may not generalize to novel combinations or to inputs requiring very different capability balances. We mitigate this by training on a diverse set of random combinations.
4. **Layer selection**: The choice of which residual stream layer(s) to steer is crucial. We will experiment with middle layers (e.g., layers 8, 16, 24) and potentially use multiple layers.
5. **Computational cost**: Learning the basis vectors requires gradient descent through the full model, which is expensive for 7B models. We will use LoRA-like approximations or only update a small set of parameters (e.g., the steering vectors themselves, which are just d_model-dimensional).
6. **Evaluation subjectivity**: Creative writing quality is subjective. We will use automated metrics (perplexity, diversity) and human evaluation via Amazon Mechanical Turk for a subset of samples.
