# Graph Rewiring: Dynamic Restructuring of Reasoning Graphs for Adaptive AI Agents

Short Hypothesis: Allowing an AI agent to dynamically restructure its reasoning graph (adding, removing, or merging nodes and edges) based on intermediate feedback will significantly improve performance on complex multi-step reasoning tasks, especially those requiring plan revision, compared to static graph-of-thought methods or simple backtracking.

Related Work: Existing reasoning frameworks for LLM agents include Chain-of-Thought (CoT), Tree-of-Thought (ToT), Graph-of-Thought (GoT), and ReAct. CoT uses linear steps with no revision. ToT uses tree search with backtracking but only allows retracing a single path. GoT predefines a static DAG structure and does not allow dynamic modification. ReAct interleaves reasoning and action but lacks structured graph revision. My proposal uniquely introduces dynamic graph rewiring: the agent can insert, delete, or merge nodes and edges during reasoning, enabling non-linear structural adaptation based on new information. This goes beyond simple backtracking by allowing the entire reasoning topology to change.

Abstract: Large language model (LLM) agents often struggle with complex reasoning tasks that require revising plans or assumptions after partial execution. Existing methods such as Chain-of-Thought, Tree-of-Thought, and Graph-of-Thought impose fixed reasoning structures (linear, tree, or static DAG) that limit adaptability. We propose Graph Rewiring, a novel framework where the agent maintains a dynamic reasoning graph that it can restructure on the fly. At each step, the agent can expand a node, retract a node (with backtracking), merge two nodes (combining parallel subproblems), or insert a new node between existing nodes (reformulating the reasoning path). These operations are decided by the LLM itself based on the current graph state and intermediate observations. We evaluate on HotpotQA (multi-hop QA) and a custom Dynamic Puzzle benchmark where new constraints appear mid-reasoning. Baselines include CoT, ToT, static GoT, and ReAct. Results show that Graph Rewiring significantly improves accuracy and success rate on tasks requiring plan revision, while maintaining efficiency on simpler tasks. The framework provides a principled way for agents to adapt their reasoning structure to changing information, moving toward more flexible and human-like problem solving.

Experiments: 1. Benchmarks: (a) HotpotQA (multi-hop reasoning, 100 random dev questions), (b) Custom Dynamic Puzzle: a multi-step puzzle where after the agent takes an initial reasoning step, a new constraint is revealed that invalidates part of the plan (20 handcrafted scenarios). 2. Baselines: CoT (standard prompting), ToT (breadth-first search with 3 branches, depth 5), GoT (static DAG with predefined decomposition), ReAct (tool-use with reasoning steps). 3. Method: The agent uses GPT-4 with a Python environment that maintains a reasoning graph as a JSON object (nodes: subproblems/observations; edges: dependencies). At each step, the LLM outputs one of four actions: (a) expand(node, subquestion) -> add child node, (b) retract(node) -> remove node and all descendants, (c) merge(node1, node2) -> combine two sibling nodes into one, (d) insert(parent_node, new_node, child_node) -> add a node between parent and child. The environment validates action legality. The LLM is prompted with the current graph and the new observation. 4. Metrics: (i) Accuracy (exact match for QA, success/fail for puzzles), (ii) Average number of reasoning steps, (iii) Number of rewiring operations per task, (iv) Success rate on dynamic puzzles. 5. Implementation details: Use OpenAI API, temperature 0.0 for reproducibility. Each run repeated 3 times. Code will be released.

Risk Factors and Limitations: 1. LLMs may produce invalid or suboptimal rewiring decisions, leading to infinite loops or degraded performance. 2. The approach could be computationally expensive due to multiple LLM calls per step (one for action selection, one for execution). 3. The dynamic puzzle benchmark is artificial; real-world applicability may be limited. 4. The method might overcomplicate simple problems where linear reasoning suffices. 5. The rewiring operations rely on the LLM's ability to understand graph structure, which may be limited for large graphs. 6. We assume the agent receives explicit feedback when a plan fails; in real settings, this feedback may be noisy or absent.
