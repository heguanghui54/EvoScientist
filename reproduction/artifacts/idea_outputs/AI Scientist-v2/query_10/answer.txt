# Compositional SQL Synthesis via Program Decomposition: A Modular Approach to Text-to-SQL Generalization

Short Hypothesis: The primary limitation in compositional generalization for Text-to-SQL is not the language model's reasoning capacity, but the lack of explicit decomposition of SQL queries into independent, reusable sub-queries during training. By forcing the model to learn a hierarchical decomposition of SQL into atomic operations (e.g., single-table projections, filters, joins) and then recomposing them, we can achieve significantly better generalization to unseen combinations of operations and schemas.

Related Work: Existing Text-to-SQL methods (e.g., T5-Spider, PICARD, S$\text{^3}$QL) treat the SQL as a flat sequence or use tree-based decoders that predict the SQL abstract syntax tree (AST) but do not explicitly decompose into independent sub-queries. Compositional generalization has been studied in semantic parsing (e.g., SCAN, COGS, PCFG-based methods) but not applied to Text-to-SQL with a focus on SQL's modular structure. Our proposal introduces a novel decomposition strategy that breaks SQL into sub-queries at the clause level (SELECT, FROM, WHERE, JOIN) and learns to generate them independently before recomposing, which is a clear departure from existing end-to-end approaches.

Abstract: We propose Compositional SQL Synthesis via Program Decomposition (CSSPD), a framework that improves compositional generalization in Text-to-SQL by explicitly decomposing complex SQL queries into simpler, independent sub-queries. Current state-of-the-art models struggle when faced with novel combinations of operations or database schemas not seen during training. We hypothesize that this failure stems from the lack of modularity in the generation process: models learn spurious correlations between input tokens and output SQL sequences rather than the underlying compositional structure. CSSPD addresses this by training a hierarchical decoder that first predicts a set of atomic sub-query templates (e.g., single-table SELECT, filter conditions, JOIN conditions) and then fills in the specific columns and values. During inference, the model generates sub-queries independently and recomposes them into the final SQL. We evaluate on a new compositional split of the Spider dataset, where we hold out certain combinations of SQL clauses and schema patterns. Experiments show that CSSPD outperforms standard seq2seq and AST-based baselines by up to 15% exact set match accuracy on compositional splits, while maintaining competitive performance on the standard Spider test set. This work demonstrates that explicit decomposition is a simple yet effective inductive bias for compositional generalization in Text-to-SQL.

Experiments: 1. **Dataset Construction**: Create a compositional split of Spider by grouping SQL queries based on the set of clause types (e.g., SELECT, WHERE, GROUP BY, JOIN) and schema patterns. Hold out specific combinations (e.g., queries with both GROUP BY and HAVING, or queries joining more than 2 tables with aggregation). This split tests generalization to unseen compositions. 2. **Baselines**: (a) T5-base fine-tuned on Spider (seq2seq), (b) T5-base with AST-based decoder (e.g., TreeGen), (c) T5-base with chain-of-thought prompting (CoT). 3. **CSSPD Implementation**: Use T5-base encoder. Decoder is modified to first produce a set of sub-query embeddings (using a slot-based attention mechanism). Each sub-query is generated independently via separate decoder heads, then a recomposition module uses cross-attention to combine them into the final SQL sequence. Training uses a multi-task loss: independent sub-query losses + final SQL loss. 4. **Metrics**: Exact Set Match (ESM) accuracy (order-invariant), Execution Accuracy (ExeAcc), and Compositional Generalization Accuracy (CGA, i.e., accuracy on the held-out compositional split). 5. **Ablations**: (a) Remove the recomposition module and just concatenate sub-queries, (b) vary number of sub-query slots, (c) use pre-defined sub-query types vs. learned clustering. All experiments run on a single GPU (e.g., RTX 3090) with standard hyperparameters.

Risk Factors and Limitations: 1. **Decomposition Ambiguity**: Some SQL queries may not decompose cleanly into independent sub-queries (e.g., nested subqueries, window functions). We mitigate by focusing on standard SELECT-FROM-WHERE-GROUP BY-JOIN queries, which cover the majority of Spider. 2. **Increased Model Complexity**: The hierarchical decoder adds parameters and training time, but we expect the modular structure to improve sample efficiency. 3. **Evaluation Bias**: The compositional split may not reflect real-world distribution shifts; we also evaluate on standard Spider to ensure general performance is not sacrificed. 4. **Scalability**: The number of sub-query slots is fixed; future work could dynamically predict the number of sub-queries. 5. **Failure Cases**: Complex queries with multiple nested levels may still fail; we limit scope to 2-level nesting.
