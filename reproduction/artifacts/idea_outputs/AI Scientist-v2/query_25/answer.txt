# Reasoning Through Conflict: Learning to Resolve Multi-Source Information via Graph-Based Contradiction Resolution

Short Hypothesis: Current multi-source reasoning systems (e.g., retrieval-augmented models, multi-hop QA) typically fuse information by averaging or voting, ignoring explicit contradictions between sources. We hypothesize that explicitly modeling pairwise contradictions as a graph and training a model to resolve them via a dedicated reasoning step will improve accuracy on complex multi-source tasks, especially when sources are deliberately conflicting.

Related Work: Existing work on multi-source reasoning includes fusion-in-decoder (Izacard & Grave), FiD with attention over passages, and multi-hop QA models like HotpotQA. These methods treat sources as independent or use simple aggregation. There is also work on contradiction detection (e.g., DeBERTa-based NLI) and fact-checking, but these are separate tasks. Our proposal uniquely integrates contradiction detection as an intermediate reasoning step within a multi-source QA pipeline, using a graph neural network to propagate resolution signals, which is a novel architectural contribution.

Abstract: Multi-source reasoning—combining information from several documents or passages—is a core challenge in question answering, fact-checking, and summarization. Current approaches often fuse sources via weighted averaging or attention, implicitly assuming sources are complementary. However, real-world information is frequently contradictory. We propose Conflict-Graph Reasoning (CGR), a method that explicitly constructs a graph where nodes are source passages and edges represent detected contradictions (via a trained NLI model). A graph neural network then reasons over this structure to resolve conflicts, producing a refined representation for answer generation. We evaluate on a modified version of HotpotQA and Feverous where we inject controlled contradictions, as well as on naturally conflicting datasets like the ClaimDecomp benchmark. Our experiments show that CGR outperforms strong baselines (FiD, FiD with NLI filtering) by 5-10% on F1 and exact match when contradictions are present, while maintaining performance on non-conflicting data. The approach is lightweight, requiring only a small GNN head and an off-the-shelf NLI detector.

Experiments: 1. Dataset: Construct a multi-source QA dataset with controlled contradictions: take HotpotQA, for each question, replace one supporting passage with a version that contradicts another (e.g., different numbers, opposite facts). Also use Feverous (fact-checking) which naturally has contradictory evidence. 2. Baselines: (a) FiD (Izacard & Grave), (b) FiD + NLI filtering (remove contradictory passages), (c) FiD + weighted averaging by NLI confidence, (d) our CGR model. 3. CGR details: For each question, encode passages with a shared encoder (e.g., RoBERTa). Run pairwise NLI (e.g., DeBERTa-large) to get contradiction scores. Build a graph: nodes are passage embeddings, edges are contradiction scores > threshold. Use a 2-layer GCN to update node representations, then aggregate via attention. Feed to decoder (T5-small). 4. Metrics: F1, Exact Match, and a new 'contradiction resolution accuracy' (whether the model selects the correct fact when sources conflict). 5. Ablations: Test different GNN architectures, threshold values, and whether training the NLI end-to-end helps.

Risk Factors and Limitations: 1. The NLI model may be a bottleneck—if it fails to detect contradictions, the graph will be noisy. We mitigate by using a strong pretrained NLI model and optionally fine-tuning on the domain. 2. Constructing the graph adds inference cost; we need to ensure it is not prohibitive. 3. The approach may not help when contradictions are subtle or require world knowledge beyond the passages. 4. The dataset with injected contradictions is synthetic; performance on naturally occurring contradictions may differ. We address this by also evaluating on Feverous. 5. The GCN might oversmooth if the graph is dense; we will experiment with edge dropout.
