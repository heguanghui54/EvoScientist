# Dynamic Retrieval via Reasoning Paths: Solving Multi-Hop RAG with Iterative Query Refinement

Short Hypothesis: Current RAG systems for multi-hop reasoning often retrieve all documents at once or in a fixed order, missing the opportunity to use intermediate reasoning steps to guide subsequent retrievals. We hypothesize that dynamically refining retrieval queries based on the evolving reasoning state—e.g., partial answers, identified entities, or unresolved sub-questions—will significantly improve accuracy and efficiency on multi-hop QA tasks, as it mimics human step-by-step information gathering.

Related Work: Existing work like Self-RAG (Asai et al., 2023) uses the LLM to decide when to retrieve but does not adapt the query based on reasoning state. IRCoT (Trivedi et al., 2022) interleaves reasoning and retrieval but uses fixed prompts for each step. Tree-of-Thoughts RAG (Yao et al., 2023) explores multiple reasoning paths but at high computational cost. Our proposal differs by introducing a lightweight 'reasoning tracker' that maintains a structured representation of the current reasoning state (e.g., a set of known facts and pending sub-questions) and uses it to generate context-aware queries for the retriever. This is not a trivial extension because it requires a novel mechanism to compress reasoning state into effective queries and a training procedure to align the retriever with reasoning progress.

Abstract: Multi-hop reasoning remains a fundamental challenge for Retrieval-Augmented Generation (RAG) systems, which typically retrieve documents in a single pass or with fixed iterative schemes. We propose Reasoning-Aware Retrieval (RAR), a novel framework that dynamically refines retrieval queries based on the evolving reasoning state of a large language model (LLM). Instead of using the original question repeatedly or simple concatenation of previous outputs, RAR maintains a compact 'reasoning state' consisting of confirmed facts, pending sub-questions, and unresolved entities. At each reasoning step, the LLM generates a context-aware query by attending to this state, which is then used to retrieve relevant documents. The retrieved information updates the state, enabling a closed-loop process that mimics human step-by-step search. We implement RAR by training a small query generation module with reinforcement learning, where the reward is based on the accuracy of the final answer and the efficiency (number of retrieval steps). Experiments on multi-hop datasets like HotpotQA, 2WikiMultihopQA, and MuSiQue show that RAR outperforms baselines (including IRCoT, Self-RAG, and standard iterative RAG) by 5-10% in F1 and answer accuracy, while reducing the total number of retrieval calls by 20%. Our work highlights the importance of reasoning-aware retrieval for complex QA and provides a practical, efficient solution.

Experiments: We will evaluate on three multi-hop QA datasets: HotpotQA (distractor setting), 2WikiMultihopQA, and MuSiQue. Baselines include: (1) standard single-pass RAG, (2) iterative RAG with fixed query (repeat original question), (3) IRCoT, (4) Self-RAG, and (5) Tree-of-Thoughts RAG (with beam size 3). Our method RAR: We use a frozen LLM (e.g., Llama-3-8B) as the generator. A lightweight query generator (a 2-layer MLP) takes as input the reasoning state (a concatenation of embeddings of current facts and pending questions, extracted via a small encoder) and outputs a query embedding. The retriever is a dense retriever (Contriever-MS MARCO) which is fine-tuned jointly with the query generator using REINFORCE. Reward = 1 if final answer is correct (exact match) else 0, minus a small penalty per retrieval step (0.01). Training on 5k samples from HotpotQA. Evaluation metrics: Exact Match (EM), F1 score, average number of retrieval steps, and total inference time. We also analyze the quality of generated queries (e.g., overlap with gold sub-questions).

Risk Factors and Limitations: 1. Training complexity: Joint training of query generator and retriever may be unstable; we may need careful reward shaping. 2. Generalization: The reasoning state representation might overfit to the training datasets; we test on unseen domains. 3. Computational overhead: Maintaining and updating reasoning state adds some latency, but we expect net savings due to fewer retrieval calls. 4. The approach assumes the LLM can reliably produce intermediate reasoning steps; for less capable models, the state may be noisy. 5. The query generator's capacity is limited; scaling to very complex multi-hop (e.g., 5+ hops) might require more sophisticated state compression.
