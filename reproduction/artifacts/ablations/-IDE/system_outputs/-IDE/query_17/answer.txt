Schema-Conditional Information Extraction via Cross-Field Consistency
Verification### ProblemExisting information extraction systems are typically
trained for fixed, predefined schemas — a given NER or RE model extracts entity
types and relations from a closed set. When applied to a new domain or a novel
extraction schema, practitioners must either annotate hundreds to thousands of
examples for fine-tuning or resort to zero-shot prompting of large language
models. The former is expensive and slow; the latter suffers from field-level
hallucination, missing values, and internal inconsistency across extracted
fields (e.g., extracting an "age" field of25 and a "graduation_year" field
of1995 for the same person — a coherence violation a human would catch). No
existing approach explicitly models cross-field consistency as a learnable
signal at extraction time, and current evaluation benchmarks measure field-level
F1 in isolation, masking these structural errors.

HypothesisAugmenting a schema-conditional extractor with a lightweight
cross-field consistency verification module — trained on automatically generated
consistency-violation examples — will improve extraction precision by5–8 points
on unseen schemas compared to an equivalent extractor without verification,
while preserving recall within2 points. The verification module learns to detect
coherence patterns across fields (temporal ordering, numeric range plausibility,
type compatibility) and can reject or revise inconsistent extractions without
additional human annotation.

MethodWe propose a two-stage architecture:

Stage1 — Schema-Conditional Field Extractor. A frozen instruction-tuned language
model (e.g., Llama-3-8B-Instruct) is prompted per schema field with the source
document and a structured field description. Each field is extracted
independently as a span or set of spans, producing a raw extraction table with M
fields and N candidates per field.

Stage2 — Cross-Field Consistency Verifier. A smaller encoder (e.g.,
DeBERTa-v3-base) is trained on a dataset of (schema, extraction_table,
consistency_label) triples. Positive examples are drawn from verified gold
extractions. Negative examples are synthetically generated by injecting
controlled violations: (a) temporal violations — extraction year earlier than
birth year for a person; (b) numeric range violations — age inconsistent with
date-of-birth; (c) type cardinality violations — more CEOs listed than a company
has had in a given period; (d) mutual exclusion violations — same entity
assigned two incompatible attribute values. The verifier scores each extraction
table holistically, and low-scoring tables trigger a targeted re-extraction pass
on the violating fields only (rerun Stage1 for those fields with the
inconsistency highlighted in the prompt).

The pipeline is trained once on a diverse set of schemas and documents, then
evaluated on held-out schemas never seen during training.

Dataset & BenchmarkTraining: We construct a multi-schema IE dataset by
sampling50 distinct extraction schemas (3–8 fields each) from the Schema-Guided
Dialogue schema bank and from crowdsourced annotation guidelines on10K documents
drawn from Wikipedia, biomedical abstracts (PubMed), and financial reports (SEC
filings). For each (schema, document) pair, we generate gold extraction tables
using expert annotators. Consistency-violation negatives are synthesized
automatically at a3:1 negative-to-positive ratio.

**Evaluation (held-out):**15 unseen schemas on1,500 documents, balanced across
the three domains. Critically, we add a schema-shift split where the evaluation
schema has field types systematically different from any training schema (e.g.,
training schemas have person-entity fields; the shift split introduces
organizational governance fields with no overlap in semantic types).

Evaluation Metrics| Metric | Definition |

|---|---| | Field-level F1 | Per-field span precision/recall against gold,
macro-averaged | | Table-level coherence | Fraction of extraction tables with
zero consistency violations (human-judged on held-out set) | | Precision@K
(field) | Precision on the top-K extracted candidates per field | |
Schema-transfer gap | F1 drop on schema-shift split vs. in-distribution held-out
schemas | | Re-extraction overhead | Fraction of fields requiring a second pass
(efficiency metric) |

Primary metric is Table-level coherence. Secondary is Field-level F1 on the
schema-shift split.

Baselines1. Zero-shot LLM (no verification): Same Stage-1 extractor, no
consistency verifier. Directly measures the benefit of the verification stage.

 2 ChatIE (Wei et al.,2023): Conversational IE that interleaves extraction with
   self-questioning — the closest existing approach with implicit consistency.
 3 Fine-tuned seq2seq (UIE; Lu et al.,2022): Unified IE fine-tuned on all
   training schemas with a BART encoder-decoder, evaluated zero-shot on held-out
   schemas.
 4 Constraint CRF (Goldin & Church,2020): A structured prediction baseline with
   hand-coded consistency constraints (upper bound for verifier with perfect
   rules — we compare learned vs. hand-coded consistency).

Ablations1. w/o cross-field verifier: Remove Stage2 entirely, use raw Stage1
extraction only.

 2 w/o synthetic negatives: Train verifier on gold extractions only (positive
   examples only — degenerates to a coling model; expected to fail, confirming
   that negative synthesis is essential).
 3 Single-field verifier: Replace the cross-field verifier with a per-field
   confidence threshold (same compute budget, no cross-field signal).
 4 Verifier-as-ranker: Instead of re-extraction, use the verifier to rank
   extraction tables from N perturbed prompts — tests whether the verifier is
   more useful for selection or correction.
 5 w/o targeted re-extraction: Low-scoring tables are discarded rather than
   repaired — isolates the value of the re-extraction loop.

Expected Failure Modes1. Verifier overfitting to synthetic artifacts. The
automatically generated consistency violations may follow detectable patterns
(e.g., always flipping one specific field) that do not generalize to real
extraction errors. Mitigation: A human-annotated consistency-violation set (500
tables) held out for verifier development; if verifier accuracy drops more
than15% on human vs synthetic violations, we iteratively improve the synthesis
procedure.

 2 Re-extraction loop oscillation. Targeted re-extraction may flip a violation
   to a different violation type, causing multiple passes without convergence.
   Mitigation: Cap re-extraction at2 rounds; if still inconsistent, return the
   highest-scoring table and log the failure for analysis.
 3 Type collision in schema-shift condition. If the verifier has never seen a
   particular field type (e.g., "board voting power"), it may assign near-random
   consistency scores. Mitigation: The verifier is built on a pretrained encoder
   that receives field descriptions (not just field IDs), enabling zero-shot
   generalization via semantic similarity. Measure this explicitly via the
   schema-transfer gap.
 4 Precision gain at recall cost. The verifier may be too aggressive, rejecting
   valid extractions and lowering recall. Mitigation: The success criterion
   requires recall within2 points of the baseline. We calibrate the verifier
   threshold on a validation set to enforce this constraint.

Limitations1. Schema scope. The method assumes the extraction schema is provided
as natural-language field descriptions. Schemas requiring complex nested
structures (e.g., hierarchical event arguments with optional slots) are not
supported and would require a recursive extension.

 2 Single-document only. Cross-field consistency is verified within a single
   extraction table. Cross-document consistency (entity linking across
   documents) is out of scope.
 3 Annotation cost for gold extraction tables. While consistency negatives are
   synthetic, the gold extraction tables for training require expert annotation.
   The10K-table training set is a significant upfront cost. Future work could
   explore bootstrapping from distantly supervised tables.
 4 Language and domain. Evaluated on English documents from three domains only.
   Generalization to low-resource languages, where the frozen LLM extractor is
   weaker, is unknown and likely requires language-adaptive prompting.
 5 No open-schema extension. The verifier is trained on a fixed set of50
   training schemas. If a completely novel constraint type appears at test time
   (e.g., a regulatory compliance rule that no existing training schema
   encodes), the verifier cannot detect violations of that type. This is a
   fundamental limitation of the supervised verification approach versus a
   rule-based or retrieval-augmented alternative.
