Research Proposal: Compositional Reasoning Under Distraction — When Do Agentic
Workflows Break Down?

Title**"Plan-Trace-Verify: A Controlled Study of Multi-Step Compositional
Reasoning in LLM Agents Under Distractor Conditions"**

--------------------------------------------------------------------------------

Problem
LLM-based agents today are deployed on tasks that require chaining
multiple reasoning steps (e.g., "book a flight, check the weather at the
destination, then find restaurants within budget"). These agents frequently fail
not because individual steps are hard, but because they lose the thread when
intermediate results contradict expectations or when irrelevant context
(distractors) is injected mid-trajectory.

The core problem: existing benchmarks evaluate reasoning in clean, single-turn
settings (e.g., GSM8K, MATH, HotpotQA), but agentic reasoning involves iterative
plan-trace cycles where earlier outputs become inputs to later steps. We lack a
controlled benchmark that isolates the effect of "distractor injection" —
irrelevant or misleading intermediate observations — on compositional reasoning
accuracy.

--------------------------------------------------------------------------------

Hypothesis
H₁ (Primary): Injecting task-irrelevant but semantically plausible
observations mid-trajectory degrades LLM agent compositional reasoning accuracy
by ≥25% relative to the no-distractor baseline, even when the underlying
reasoning path is unchanged.

H₂ (Mechanism): The degradation is primarily driven by retrieval interference
(the agent attends to distractor tokens in subsequent reasoning steps) rather
than plan corruption (the agent incorrectly revises its plan). This implies that
improving selective attention (e.g., structured memory) will help more than
improving planning ability.

H₃ (Mitigation): A simple Plan-Trace-Verify loop — where the agent explicitly
writes down its plan before execution, traces each step against the plan after
receiving observations, and verifies consistency before proceeding — recovers
≥80% of the performance gap relative to the no-distractor baseline.

--------------------------------------------------------------------------------

Method
### Framework: Plan-Trace-Verify (PTV)

We define three agent strategies to compare:

1 Direct-ReAct (baseline): Standard ReAct-style agent — thinks, acts, observes
in a flat loop with no explicit plan tracking.
2 Plan-then-Execute (ablation control): The agent writes a plan (as pseudocode
or bullet points) before execution, then follows it linearly, but does not
re-check consistency after each observation.
3 Plan-Trace-Verify (PTV) (proposed): The agent:

• Plan: Writes an explicit, numbered plan with preconditions and expected
postconditions for each step.
• Trace: After each observation, appends a structured trace entry: [Step N]
expected=<...> observed=<...> match=<yes|no>.
• Verify: Before the next step, runs a consistency check. If match=no, the
agent must decide: (a) proceed (the mismatch is benign), (b) re-plan from
this state, or (c) request clarification.

Distractor Injection ProtocolFor each task, we construct three conditions:

• Clean: Standard trajectory, no distractors.
• Weak distractors: One irrelevant observation per task, semantically related
to the domain but logically unnecessary (e.g., a flight search returns "Did
you know? Economy seats have30-inch pitch." between steps).
• Strong distractors: Two to three irrelevant observations, written to
plausibly contradict an intermediate expectation without actually
invalidating the correct path (e.g., a weather lookup returns "Rain expected"
when the correct reasoning only needs temperature).

Distractors are inserted at fixed positions (after step1, after step2) to ensure
controlled comparison.

--------------------------------------------------------------------------------

Ablations1. Distractor position: Do distractors hurt more at early vs late
steps?

2 Distractor type: Semantic distractors vs random tokens vs plausible-but-wrong
facts — which causes the most degradation?
3 Plan granularity: Does a detailed plan (per-step pre/post conditions) help
more than a brief plan (bullet list)?
4 Verification frequency: Verify after every step vs every2 steps vs
end-of-trajectory — is there a sweet spot?
5 Memory structure: Instead of PTV's trace-and-verify, use a simple scratchpad
with a "recent observations" summary — does structured memory alone match
PTV?
6 Model scale: Does the gap between PTV and Direct-ReAct shrink or grow at
larger model sizes?
